UG-LMS 特殊执行名单

Credit Application 页面高保真还原 · 数据来源：https://mtn-uganda-lms-web-test.mindigitaltech.com/credit-application

一、目标与范围

把一个真实线上页面（UG LMS 运营后台的 Credit Application）完整还原成可在 Axhub Make 里预览、批注、迭代的原型，作为「UG-LMS 特殊执行名单」需求的原型承载页。

  • 还原对象：页面本体（侧边菜单 + 顶栏 + 查询表单 + 列表卡片）。
  • 不包含：真实数据、查询/导出等后端逻辑、路由跳转。
  • 视口基准：1209 × 824（导出包采集时的浏览器视口）。

二、数据来源与还原方法

输入是 Axhub 导出包 AI-Credit-Application-complete.zip（mode: full，187 个节点 / 102 套样式 / 3 档响应式截图）。按包内 README 的「精细还原（高保真）」指引执行：

数据源用途
screenshot.png视觉真相，所有偏差以它为准
structure/doms.jsonDOM 层级、文本、内联 SVG、元素尺寸
structure/styles.json每个节点的精确 computedStyle + Tailwind 类名
theme.jsonlogo / 头像 / 空状态插图（内嵌 base64）
topology/、sections/页面分区与固定层信息

还原脚本按 DOM 树逐节点重建 HTML，并把 computedStyle 原样落到 CSS；导出包缺失的部分用下列方式补齐：

  • 图标 sprite：导出包只保留了 <use xlink:href="#icon-xxx">，符号定义取自本地 LMS 前端仓库 src/assets/iconfont/iconfont.js，内联进页面。
  • 表格列宽：导出丢失 <col>，按表头实测宽度补回。
  • 空状态跨列：导出丢失 colspan，按「单单元格行」规则补回。
  • 边框：导出的 border 是浏览器序列化简写（形如 0px 0px 1px none none solid rgb(...) rgb(...) rgb(...)），浏览器不认，已按四边拆解重写。
  • 样式优先级：导出器给的 Tailwind 类是近似值（如 pl-7=28px，实际 30px），因此精确 computedStyle 放在工具类之后，保证覆盖。

四、验收

还原结果与原始截图做逐像素比对（同视口 1209×824）：

  • 平均绝对像素差 1.5 / 765；差异超过阈值的像素占比 0.92%。
  • 残留差异几乎全部来自横向滚动条（macOS overlay 滚动条只在滚动时显现，截图里恰好被采集到），其余为文字抗锯齿。
  • 标题、表头、表单、侧边菜单、图标、头像等关键区块的位置与配色均已逐项比对一致。

五、已知限制

  • 导出包只采了单一视口（1209×824），computedStyle 与元素尺寸都按该视口固化，因此平板/手机断点的重排未还原。
  • 宽度自适应以 1209px 为基准向上铺满；窄于 1209px 时仍按基准排布，可能出现横向滚动（导出包未采集更窄断点）。
  • 表格横向滚动条为浏览器 overlay 行为，静态截图不一定可见。
  • 导出、路由与真实数据未接入；名单查询、分页、增删改均为前端内存模拟。
  • 字体依赖本机字体（-apple-system / PingFang SC），跨平台渲染会有细微差异。
  • 特殊执行名单页的执行侧匹配（odid → tcid 优先级）与跨层级共存语义只做文档口径，原型不模拟执行端；「一人一标签」在原型内以「同层级同键唯一」模拟。
  • 有效期校验的时间比较使用浏览器本机时间（生产为 opco 本地时间）；记录状态按页面打开时刻派生。
  • 批次列表的分页与筛选：需求已列；原型演示数据不足一页，暂未体现。

演示数据与交互口径

  • 演示数据为确定性生成（时间按小时取整，同一小时内刷新结果一致）；初始 4 个导入批次（3 个已处理 + 1 个处理失败），名单共 1,240 条；时间窗以当前时间为基准分布（生效中 / 未生效 / 已失效，少量已停用）。
  • 增量导入联动：上传预览「解析 / 新增 / 覆盖 / 非法」为本次文件口径；导入通过后名单条数 = 原条数 + 新增；批次详情保留解析 / 新增 / 覆盖三个数字。
  • 文件下载：批次「下载原文件」——本次会话上传的文件按原始文件名下载；种子批次按确定性生成的示例 CSV 下载（含处理失败批次）。上传校验失败可「下载失败明细」（CSV：行号 + 原行字段 + 失败原因列）。
  • 演示整批拦截：上传文件名包含 非法 / invalid / fail / error 时，模拟校验失败（单 ID 互斥、ID 缺失、时间格式、开始时间早于当前、失效早于生效、组不在预设、组与标签不匹配等），整批放弃并列出失败明细；其余文件名模拟全部通过。触发词仅为演示开关，不代表真实校验逻辑；文件内同键重复按「后行覆盖前行」属合法行为。
  • 单条新增：标签层级切换只显示对应 ID 输入框；选择明细组后层级/执行标签自动带出并锁定（选「不指定」解锁）；同键已存在时拦截提示「新增不会覆盖」；开始时间早于当前（5 分钟宽限）被拦截。
  • 执行端匹配口径（文档口径，原型不模拟）：先按 overdraft_id 查账户级、命中即执行；未命中再按 third_customer_id 查用户级；都未命中走常规。

附录：技术实现说明

文件结构

src/prototypes/ug-lms-special-list/：index.tsx、page.html、static-style.css、assets/、annotation-source.json、.spec/spec.html。

实现要点

  • page.html 由导出包的 DOM 树逐节点生成，保留原始 class / id / 内联尺寸，宿主为 #root-master。
  • 图标 sprite 内联在 page.html 顶部（隐藏 svg），保证离线可用。
  • 折叠子菜单的 <li>/<ul> 不写死高度，由展开状态决定；interaction.js 负责点击切换，index.tsx 以脚本注入方式加载它（innerHTML 不执行 script）。
  • 可翻译文案在 DOM 上带 data-en / data-zh（输入框为 data-en-placeholder / data-zh-placeholder），lang.js 负责切换并记住选择。
  • lang.js 的 apply() 支持无参调用：缺参时回退到当前语言。其它脚本在重渲染后会调 window.__ugApplyLang()，若不兜底会把 data-lang 写成 "undefined" 导致整页退回英文。
  • static-style.css 顺序为：全局重置 → 补齐的 Tailwind 工具类 → 精确 computedStyle → antd 子菜单箭头与选中态样式；后两者覆盖前两者。
  • 生成脚本：<UG工作区>/credit-application-clone/work/build.py（还原）与 export_make.py（导出到本原型）。
  • special-list.js 为自包含 IIFE（字典 → 确定性 mock 数据 → 状态 → 渲染 → 事件绑定）；样式集中在 static-style.css 的「特殊执行名单页」段落（含 Filters、行操作与批次详情新增段）。

已知限制

同「五、已知限制」；其中响应式断点缺失源于导出包只包含单视口的计算样式。
